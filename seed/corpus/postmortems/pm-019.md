## Summary
On 2024-12-24, inventory-service experienced elevated latency and errors due to ERR_POOL_EXHAUSTED. Customers reported checkout failures.

## Impact
Approximately 17% of requests failed for 37 minutes. Revenue impact estimated at $49k.

## Timeline
- 2024-12-24 01:10 - First alert fired for inventory-service.
- 2024-12-24 01:15 - On-call paged.
- 2024-12-24 01:22 - ERR_POOL_EXHAUSTED observed in logs.
- 2024-12-24 01:35 - Mitigation applied: restarted connection pool.
- 2024-12-24 01:50 - Service recovered.

## Root Cause
The root cause was ERR_POOL_EXHAUSTED in inventory-service. The connection pool became saturated because upstream dependency slowed down, causing requests to pile up and everything to slow down. No code change to pool sizing; load exceeded configured limits.

## Contributing Factors
- Missing autoscaling for inventory-service.
- Alert threshold too high.
- Runbook not linked from alert.

## Remediation
Increased pool size and added circuit breaker. Deployed hotfix to inventory-service.
