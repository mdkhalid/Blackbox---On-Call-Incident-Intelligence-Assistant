## Summary
On 2024-06-07, notification-service experienced elevated latency and errors due to ERR_CONN_REFUSED. Customers reported checkout failures.

## Impact
Approximately 18% of requests failed for 49 minutes. Revenue impact estimated at $44k.

## Timeline
- 2024-06-07 01:10 - First alert fired for notification-service.
- 2024-06-07 01:15 - On-call paged.
- 2024-06-07 01:22 - ERR_CONN_REFUSED observed in logs.
- 2024-06-07 01:35 - Mitigation applied: restarted connection pool.
- 2024-06-07 01:50 - Service recovered.

## Root Cause
The root cause was ERR_CONN_REFUSED in notification-service. The connection pool became saturated because upstream user-service slowed down, causing requests to pile up and everything to slow down. No code change to pool sizing; load exceeded configured limits.

## Contributing Factors
- Missing autoscaling for notification-service.
- Alert threshold too high.
- Runbook not linked from alert.

## Remediation
Increased pool size and added circuit breaker. Deployed hotfix to notification-service.
