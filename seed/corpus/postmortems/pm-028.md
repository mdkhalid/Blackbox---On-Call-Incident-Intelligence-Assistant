## Summary
On 2024-09-08, checkout-service experienced elevated latency and errors due to ERR_POOL_EXHAUSTED. Customers reported checkout failures.

## Impact
Approximately 18% of requests failed for 47 minutes. Revenue impact estimated at $32k.

## Timeline
- 2024-09-08 01:10 - First alert fired for checkout-service.
- 2024-09-08 01:15 - On-call paged.
- 2024-09-08 01:22 - ERR_POOL_EXHAUSTED observed in logs.
- 2024-09-08 01:35 - Mitigation applied: restarted connection pool.
- 2024-09-08 01:50 - Service recovered.

## Root Cause
The root cause was ERR_POOL_EXHAUSTED in checkout-service. The connection pool became saturated because upstream payment-gateway slowed down, causing requests to pile up and everything to slow down. No code change to pool sizing; load exceeded configured limits.

## Contributing Factors
- Missing autoscaling for checkout-service.
- Alert threshold too high.
- Runbook not linked from alert.

## Remediation
Increased pool size and added circuit breaker. Deployed hotfix to checkout-service.
