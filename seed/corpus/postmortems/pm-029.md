## Summary
On 2024-10-16, inventory-service experienced elevated latency and errors due to ERR_DB_DEADLOCK. Customers reported checkout failures.

## Impact
Approximately 16% of requests failed for 55 minutes. Revenue impact estimated at $31k.

## Timeline
- 2024-10-16 01:10 - First alert fired for inventory-service.
- 2024-10-16 01:15 - On-call paged.
- 2024-10-16 01:22 - ERR_DB_DEADLOCK observed in logs.
- 2024-10-16 01:35 - Mitigation applied: restarted connection pool.
- 2024-10-16 01:50 - Service recovered.

## Root Cause
The root cause was ERR_DB_DEADLOCK in inventory-service. The connection pool became saturated because upstream dependency slowed down, causing requests to pile up and everything to slow down. No code change to pool sizing; load exceeded configured limits.

## Contributing Factors
- Missing autoscaling for inventory-service.
- Alert threshold too high.
- Runbook not linked from alert.

## Remediation
Increased pool size and added circuit breaker. Deployed hotfix to inventory-service.
