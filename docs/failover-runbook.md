# Region Failover Runbook

Applies when a region's primary database or the region itself is unavailable. The
target state is: the surviving region owns the affected tenants' writes, and no
request writes a non-home region.

## Preconditions

- Tenant → home region is stored in `tenant_regions`; the DB is authoritative, a JWT
  `region` claim is advisory only.
- `REGION_WRITE_PINNING=true` on every regional release. A request that reaches a
  non-home region gets `421` with `X-Blackbox-Home-Region`, which the edge uses to
  retry at the home region.
- `DATABASE_POOL_PRE_PING=true`, so a repointed endpoint heals stale connections
  instead of surfacing errors.

## Steps

1. **Declare the incident and freeze the region.** Stop the ingress from sending new
   traffic to the failing region. The API keeps serving reads from its replica until
   the connection is cut.
2. **Promote the database.** Managed (Aurora Global): invoke the provider's
   failover/promote. Self-hosted: `deploy/dr/promote.sh` (or `pg_ctl promote`).
   Advisory locks are session-scoped, so promotion drops them; a turn that was in
   flight on the old primary fails and must be retried. There are no stale locks to
   clear on the new primary.
3. **Repoint the application.** Update the regional `DATABASE_URL`/`DATABASE_READ_URL`
   (External Secrets → restart pods, or the Helm release). Pre-ping replaces stale
   pooled connections.
4. **Flip tenant ownership.** For each affected tenant, set
   `tenant_regions.home_region` to the surviving region with `status='failed_over'`.
   Use the admin path or:
   ```sql
   UPDATE tenant_regions
      SET home_region = 'us-east-1', status = 'failed_over', updated_at = now()
    WHERE home_region = 'eu-west-1';
   ```
   The resolver cache is 60 s; restart pods or wait for the TTL for an immediate flip.
5. **Drain and recover jobs.** Queued jobs in the failed region's Redis are lost
   (Redis is non-authoritative). Start the worker in the surviving region; it calls
   `JobQueue.redrive()` on startup, which re-queues any job whose record survived but
   whose pending entry did not. Re-submit ingest/eval whose records are also gone.
6. **Check retrieval health.** Dense/sparse indexes are per region. If the promoted
   region's index is stale, rebuild from canonical documents:
   ```bash
   python scripts/rebuild_region_indexes.py --source seed/corpus --validate
   ```
7. **Verify.** Run the synthetic probe and one chat turn in the surviving region:
   ```bash
   python scripts/smoke_probe.py --base-url https://<survivor>
   ```
   Confirm `GET /health/ready` reports storage and runtime ready, and that a chat turn
   is persisted (`GET /api/conversations/<id>/trace`).
8. **Notify tenants** whose data residency region changed, and record the failover
   generation (`region.failover_generation`).

## Failback

Repeat the steps with the roles reversed. Move tenants back with
`docs/tenant-move-runbook.md`; do not flip `home_region` until the destination has
verified copies.

## Measured numbers

`docs/dr-drill-results.md` is generated by `scripts/dr_drill.py`. The local harness
measures a SQLite promotion; replace it with real endpoints and a `promote` callable
to measure a production failover. RTO/RPO are recorded, not estimated.
